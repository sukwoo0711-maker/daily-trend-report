### 07-31과 달라진 점 — 이번에는 실행 경로가 은닉돼 있다

07-31의 `andrej-karpathy-skills`는 README가 *"fastsetup 애플리케이션을 열어 설치하세요"* 라고 **권했을 뿐**이라, 부주의한 커밋일 가능성을 배제하지 않았다. `ratchet`은 다르다. **설치 스크립트 `bin/install.js`(읽을 수 있는 자바스크립트)가 그 실행 파일을 직접 띄우며, 방식이 은닉형이다.**

`bin/install.js`에서 직접 확인한 것(다운로드·실행 없이 소스만 읽음):

| 관측된 코드 | 성격 |
|---|---|
| `if (process.platform !== 'win32') return;` | **윈도우에서만** 동작 |
| `powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -EncodedCommand <base64>` | **실행 정책 우회 + UTF-16LE→base64 인코딩 명령** |
| `$s=New-Object -COM WScript.Shell; $s.Run('...', 0, $false)` | `0` = **창 숨김**, `$false` = 대기 안 함 |
| `spawn(exePath, [], { detached: true, stdio: 'ignore', windowsHide: true })` | **분리 실행·출력 무시·창 숨김** |
| `child.on('error', () => {}); catch {}` | **실패를 조용히 삼킴** |
| PowerShell 실패 시 `directSpawn()` 대체 경로 | **폴백까지 준비** |

정상적인 UI 실행기는 실행 정책 우회도, base64 인코딩 명령도, 창 숨김도, 오류 무시도 필요하지 않다. **여섯 가지가 한꺼번에 있는 것은 은닉 실행 패턴이다.**

**여전히 단정하지 않는 것**: 실행 파일을 **다운로드·실행·역공학하지 않았다.** 그 바이너리가 무엇을 하는지는 모르며, 악성이라고 단정하지 않는다. 다만 **전달 방식이 의도적으로 은밀하다는 것은 자바스크립트 소스에서 직접 읽은 사실**이고, 이는 07-31 시점에는 없던 근거다.

**분류(taxonomy) → 탐지(detection) → 교정(fixes)** 3단 구조가 08-01 #3의 구성과 사실상 같다. 서로 다른 저자가 같은 형태에 도달했다는 점에서, **"AI 냄새 제거"는 프롬프트 한 줄이 아니라 유형 목록 + 탐지 기준 + 교정 규칙의 세트로 다루는 것**이 정착 중인 형태로 보인다.

**이 스택에 붙는 자리**: 사용자의 `ai-tone-rules`·`gemini-plain-korean`과 같은 문제다. 08-01 #3이 "구조만 이식 가능"했던 것과 달리, 이쪽은 **UI·시각 요소 항목까지 포함**하고 영어권 기준이라 참조 범위가 넓다. 다만 한국어 규칙은 여전히 직접 만들어야 한다.

**등급 근거**: 핵심 산출물은 `SKILL.md` + 참조 마크다운 3개로 **복사만으로 이식**된다(S). `scripts/scan.mjs`는 선택적 스캐너이며 Node가 필요하므로, 스캐너까지 쓰려면 A 수준의 런타임 전제가 붙는다.
