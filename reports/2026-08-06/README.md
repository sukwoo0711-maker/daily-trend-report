### 1. `uczltw6/trace-file-lineage` — 무엇이 증거가 **아닌지**를 먼저 적어 둔다 🧾 **[S · MIT]**
**271★ · fork 3 · 생성 2026-07-29 · 최종 푸시 07-31 · `dependencies = []` · CLEAN · 계정 전체 CLEAN**

푸는 문제는 한 줄이다 — *"어떤 코드·노트북·데이터·명령·에이전트 작업이 이 파일을 만들었는가"*, 그것도 **서버도 API 키도 없이 로컬에서.** 이미지·PDF·데이터셋·모델·리포트가 어디서 나왔는지, 낡은 산출물과 고아 파일이 무엇인지, 상류가 바뀌면 무엇이 영향을 받는지를 추적한다.

**오늘 이것을 1위로 올리는 이유는 기능이 아니라 `references/confidence.md` 한 장이다.**

먼저 **확신도 어휘가 닫혀 있다.** 모든 주장은 근거 유형 하나(관측·선언·추론·확인)를 명시하고, 사용자에게는 다섯 단계 중 하나로만 보인다.

| 등급 | 뜻 |
|---|---|
| `verified` | **직접 감싼 런타임**, 명시적으로 신뢰한 수입 provenance, 또는 **사용자 확인** |
| `strong-candidate` | 증거는 강하나 검증된 인과 사건이 없음 |
| `candidate` | 쓸 만한 정황 |
| `weak-signal` | 제한적 |
| `insufficient` | **인과적 답으로 제시하지 말 것** |

그리고 *"수치 가중치와 점수는 내부 랭킹 기계장치이지 확률이 아니다"* 라고 못박는다 — 점수를 확률처럼 보이게 하지 않겠다는 선언이다.

**더 값진 것은 그다음 절이다.** 대부분의 도구가 *"무엇이 증거가 되는가"* 를 적는데, 이건 **무엇이 증거가 못 되는지를 열거한다.**

> *"타임스탬프, 파일명 어간, 디렉터리 근접성, 리터럴 호출지점, 일반 참조, 유사도, **바이트 동일성**, OCR, 동시 변경 — 이것들 **단독으로는 인과를 절대 verified로 만들지 않는다.** **바이트 동일성은 바이트를 검증하지, 생산자나 개명을 검증하지 않는다.**"*
> *"정적 쓰기 구문은 코드가 그 경로를 **생성할 수 있다**는 뜻이다. 수동 스냅샷이나 에이전트 훅은 작업 중에 경로가 **변했음을 관측**했다는 뜻이다. 텍스트·미디어 유사도는 내용이 **일치**한다는 뜻이다. **셋 중 무엇도 쓴 주체나 내보내기 사건을 증명하지 않는다.**"*

`verified`로 승격시키는 경로는 셋뿐이다 — **직접 감싼 런타임 실행, 신뢰된 수입 provenance, 사용자의 명시적 확인.** 복구되거나 불완전한 실행은 **영원히 관측 등급에 머문다.**

**이 스택에 붙는 자리**: 사용자의 `nightly-spec-code-match`가 *"사양서의 값을 소스에서 역매칭"* 하는데, 그 매칭은 정확히 위 목록의 **"유사도"·"리터럴 호출지점"** 이다 — 즉 **후보이지 확정이 아니다.** 이 문서는 그 구분을 어휘로 강제한다. `offline-knowledge-base`·`spec-defect-search`에도 같은 등급 체계를 얹을 수 있고, `low-judgment-goldset-lab`이 재려는 *"도구가 모를 때 모른다고 하는가"* 는 `insufficient` 등급의 존재 여부로 측정 가능해진다.

PowerShell에서는 `py -3 $Lineage ...`"*. 안전 규약도 스킬 본문 두 번째 줄에 있다 — *"스캔한 프로젝트 코드를 실행하지 말고, 외부 심볼릭 링크를 따라가지 말고, 시크릿 내용을 노출하지 말고, 원본 파일을 옮기지 마라."*

### 2. `tigerless-labs/design-harness` — 사람이 판정하고, 에이전트는 심부름을 한다 🗂️ **[S · MIT]**
**187★ · fork 29 · 생성 2026-07-07 · 최종 푸시 07-27 · md 124 · CLEAN · 계정 전체 오탐만**
**※ 08-05에 게이트 판정만 마치고 내용 심사를 오늘로 넘긴 항목**([원장](../../RE-ADJUDICATION.md))

부제가 곧 설계다 — *"the human adjudicates, the agent runs errands"*. 벤더·도구 선정, 문헌 조사, 실사, 경쟁 분석처럼 **추적 가능한 증거 위에 서야 하는 다툼 있는 결정**을 위한 것이다.

구조는 세 층에 자유 표면 하나다.

| 층 | 내용 | 규칙 |
|---|---|---|
| `sources/<type>/` | **증거.** 출처 하나에 카드 하나 | 에이전트가 자유롭게 수집·등급 매김. **타입 디렉터리를 스스로 만든다**(사전 목록 없음) |
| `ideas/` | **판단** | **판단은 사람만 한다.** 대화에서 사람이 말한 결정을 카드로 **전사**할 뿐 **에이전트가 지어내지 않는다** |
| `output/` | **조립**(수렴층) | **첫 조립은 사람이 시작한다.** 이후에도 **사람이 말할 때만** 바뀐다 |
| `board/` | 사람의 자유 보드 | — |

두 가지 처리 방식이 특히 이 스택과 맞는다.

- **모순은 자동 해소하지 않는다.** 기존 카드와 같은 판단이면 자동 병합하지만, **상충하면 둘 다 보드에 올려 사람이 고르게 한다.**
- **삭제가 없다.** 아이디어는 `ideas/archive/`로 옮길 뿐 **지우지 않고**, `logs.md`는 **append-only 변경 원장**이다.

**그리고 진실원이 마크다운이다** — *"마크다운이 단일 진실원이고, 캔버스 HTML·각 층의 인덱스·위치 레지스트리는 전부 **투영이며 언제든 재생성 가능하다**."* 워크스페이스 발견은 디렉터리 이름이 아니라 `.design-harness/config.json` **레지스트리만 신뢰**한다.

## 오늘의 스택 시사점

1. **증거 등급표보다 "증거가 아닌 것" 목록이 강하다.** #1이 나열한 9가지 — 타임스탬프·파일명 어간·디렉터리 근접성·리터럴 호출지점·일반 참조·유사도·바이트 동일성·OCR·동시 변경 — 은 전부 **자동화 도구가 인과라고 착각하기 쉬운 것들**이다. 긍정 목록("이러면 증거다")은 늘 확장 해석되지만 **부정 목록은 우회하기 어렵다.** `nightly-spec-code-match`의 값-역매칭은 이 목록의 "유사도"에 해당하므로 **구조적으로 후보 등급**이다 — 지금 그렇게 표기돼 있는지 확인할 일이다.
2. **자원한 상태는 추측한 상태다.** 오늘 제외한 `sssf`가 실측으로 남긴 문장이다 — 묻지 않았는데 상태판을 만든 오케스트레이터가 **존재하지 않는 테이블과 컬럼을 조회**했다. 에이전트에게 "시작할 때 현황을 요약해 줘"를 시키면 **없는 것을 지어낼 기회를 매 세션 만들어 주는 것**이다. `sssf`의 대응은 단순하다 — *"세 단계. 그리고 멈춰라."*
3. **판단권도 권한이므로 없앨 수 있다.** 08-05가 *"권한은 지키지 말고 없애라"* 를 보안 축에서 봤다면, #2는 같은 것을 **의사결정 축**에서 한다 — 에이전트가 `ideas/`에 쓸 수 있는 것을 "사람이 말한 것의 전사"로 좁히고, **상충하는 판단은 자동 병합하지 않고 둘 다 올린다.** "중립적으로 조언하라"는 지시보다 **쓸 수 있는 필드를 제한하는 편**이 지켜진다.
4. **오늘은 2건이다. 채우지 않았다.** 30일 창의 상위는 6판 연속 미디어·UI 제작 스킬이 독점하고 있고, MCP·eval 축은 이번 창에서 통과 항목이 없었다. **개수를 맞추려고 게이트를 낮추는 것이 이 저장소가 막으려는 실패**이므로 2건으로 낸다.
